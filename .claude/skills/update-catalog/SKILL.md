# Update the catalog

This repository is a curated catalog of machine-learning papers for weather, climate, ocean and sea ice. Every
published artifact is generated from a few hand-maintained inputs, so an update means: change the inputs,
then regenerate everything from them. Never edit generated files by hand; they are overwritten on the next build.

```
inputs (hand-maintained)                       generated by scripts/update.py build
  data/seeds.tsv        landmark titles         index.html, eda.html     pages (from scripts/template.html)
  data/additions.tsv    screened IDs            papers.bib, SUMMARIES.md, data/papers.json
  data/overrides.tsv    ID fixes for seeds      data/papers.duckdb       database (scripts/build_db.py)
  data/summaries.json   structured cards        analysis/EDA.md, figures/, tables/   (analysis/eda.py + report.py)
  data/category_overrides.csv  category fixes
  scripts/taxonomy.py   category rules + PERIODS
caches (keep them): data/cache_ids.json, data/cache_s2.json, data/cache_candidates_s2.json
```

Work in `.update/` (git-ignored). Python needs `duckdb pandas matplotlib` (`pip install -r requirements.txt`);
the browser check uses Playwright if it is installed.

## 0. See where things stand

```bash
python3 scripts/update.py status
```

It prints the catalog size, papers per recent year, the citation retrieval date and pending work. Read
`data/updates.md` for previous update windows. Decide the window: start about two months before the previous
update's end date, because journals and indexes publish with delay; duplicates are removed automatically.

If the user only wants fresh citation counts or a rebuild after editing rules/template, skip to step 5
(`build --refresh-citations` re-downloads all metadata; it is slow because Semantic Scholar rate-limits).

## 1. Discover candidates

```bash
cd scripts && python3 discover_recent.py --since YYYY-MM-DD [--until YYYY-MM-DD] && cd ..
```

Queries arXiv (physics.ao-ph plus ML categories with weather/climate/ocean title terms) and Crossref for ~25 key
journals, keeps papers that name the atmosphere/ocean explicitly, drops neighbouring fields, and removes papers
already in the catalog. Expect on the order of 1,000–2,000 candidates per year of window. arXiv asks for one
request every 3 s, so this takes 10–20 minutes; run it in the background.

## 2. Score them

```bash
cd scripts && python3 score_candidates.py ../data/candidates_YYYY-MM-DD.csv && cd ..
```

Adds Semantic Scholar citations, merges arXiv and journal versions, and ranks by citations per month plus a
small venue bonus. Ranking only orders the reading; it does not decide.

## 3. Screen (judgment step)

```bash
python3 scripts/update.py screen-batches --top 640 --n 4
```

Each batch interleaves high- and low-scored candidates. Screen every batch with
[references/screening.md](references/screening.md) — usually one subagent per batch, in parallel, pointing each
at the brief and its input/output file. Then apply the decisions:

```bash
cd scripts && python3 apply_screening.py ../.update/screen_out/*.json && cd ..
```

Before moving on, read the new lines at the end of `data/additions.tsv` once: check the balance across subfields,
that nothing clearly off topic slipped in, and that landmark papers you know from the period are present. If one
is missing, add it by DOI or arXiv ID (`topic<TAB>DOI:...`). Typical yield is 120–180 papers per year of window;
fewer is fine if the candidates are weak.

## 4. Fetch metadata, then summarize the new papers

```bash
python3 scripts/update.py build          # fetches Semantic Scholar records for the new IDs, rebuilds pages
python3 scripts/update.py pending-summaries --size 30
```

The build prints `UNRESOLVED` (no record found) and `MISMATCH` (the ID resolved to a different title) lines.
Semantic Scholar misses some DOIs (AIES articles, for example); the build then retries with the title recorded in
the candidates file, so only a few should remain. A mismatch is often the same paper published under a new
title; if so, update the title in `data/seeds.tsv` and `data/overrides.tsv` and rename its key in
`data/cache_ids.json`. Otherwise fix the ID in `data/overrides.tsv` or drop the entry.

Write the summary cards for each batch in `.update/sum_in/` following
[references/summary-brief.md](references/summary-brief.md) (one subagent per batch works well), then:

```bash
python3 scripts/update.py merge-summaries
```

It refuses incomplete cards and reports them; fix and rerun. Spot-check a few cards of papers you know.

## 5. Rebuild and review the analysis

```bash
python3 scripts/update.py build
```

This regenerates the pages, BibTeX, SUMMARIES.md, the database, the EDA figures and `analysis/EDA.md`. Then
review what changed, because the numbers are computed but the interpretation is yours:

- **Headlines in `analysis/EDA.md`.** They are regenerated from the data. Read them and check they still make
  sense (for example, a period with very few papers produces misleading shares).
- **Periods.** `PERIODS` in `scripts/taxonomy.py` drives the database, the report and both pages. When a new
  year starts, extend the last period or open a new one once it has enough papers (roughly 40+).
- **Categories.** New vocabulary can escape the keyword rules. Look at papers with no architecture, goal or
  data-source tag:
  ```bash
  python3 -c "import duckdb;c=duckdb.connect('data/papers.duckdb',read_only=True);print(c.sql(\"SELECT title, architectures, tasks, data_sources FROM v_papers_wide WHERE year >= 2025 AND paper_type='method' AND (len(architectures)=0 OR len(tasks)=0 OR len(data_sources)=0)\"))"
  ```
  Fix systematic gaps in `scripts/taxonomy.py`; fix single papers in `data/category_overrides.csv`.
  Rebuild after either.

## 6. Verify

```bash
python3 scripts/update.py verify
```

Checks that every paper has a summary, that the database, both pages and the EDA report all describe the same
number of papers, and (with Playwright) that both pages load without errors, every guided view produces a note
and nothing overflows at phone width. Fix anything it reports before committing.

## 7. Record and commit

Append the update to `data/updates.md` (date, window, candidates found, papers added, notes), then commit inputs
and generated files together on the working branch and push. Keep `data/candidates_*` files: they document what
was considered. If the pages are also published elsewhere (artifacts, GitHub Pages), republish them.

Report to the user: papers added per year and subfield, notable additions, what changed in the EDA headlines,
anything unresolved, and summaries marked `assessment` for new papers.

## Troubleshooting

- **HTTP 429 from Semantic Scholar**: the scripts back off and resume from caches; just rerun. Large batches can
  take an hour on a shared IP. OpenAlex is not used because its free daily quota is often exhausted.
- **Crossref returns abstracts or preprint copies** (EGU abstracts, EarthArXiv, SSRN) with the same title:
  `resolve_ids.py` already skips those DOI prefixes; add new ones to `NON_FINAL_DOI` if they appear.
- **A paper appears twice** (preprint and journal version as separate entries): add the journal ID as an
  override for the seed title, or replace the ID in `additions.tsv`, then rebuild.
- **Retrieval date**: the pages show the date citations were last downloaded; it only moves when a build fetches
  new data.
